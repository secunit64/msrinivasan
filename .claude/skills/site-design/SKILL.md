# Site design

The site is a quiet, editorial research profile: a pale paper background,
charcoal text, one muted blue accent, generous whitespace, serif headings
over a system sans body, and restrained original line art. It is not a
documentation site and not a dashboard. Keep that register when adding
anything.

Everything visual lives in `src/styles/site.css`. The header, footer and
`<head>` are generated by `scripts/layout.mjs` so every page shares them.
Framework's own chrome is switched off in `observablehq.config.ts`
(`sidebar`, `pager`, `toc`, `search` all false; `globalStylesheets: []` so
no Google Fonts request is made).

## Tokens

Set once in `:root` of `site.css`; Framework's default stylesheet consumes
the `--theme-*` names, which is why they are overridden rather than invented.

```
--theme-background        #fafbf9   page
--theme-background-alt    #f0f3f1   cards, figure captions, notices
--theme-foreground        #253139   body text
--theme-foreground-alt    #142833   headings, active nav
--theme-foreground-muted  #55636a   secondary text, ledes
--theme-foreground-focus  #245d7c   the accent: links, focus rings, primary button
--theme-foreground-faint  #78878c / fainter #c6d0d0 / faintest #e2e7e4  rules
--sans-serif  -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
--serif       "Iowan Old Style", "Palatino Linotype", Palatino, Georgia, serif
--mono        ui-monospace, "SFMono-Regular", Consolas, monospace
```

Hairline rules use `#dce3df`; card borders `#d9e2df`/`#dce3df`. There is one
accent. Resist adding a second colour; use weight, size and spacing instead.

## Type

- Body: sans, 16px, line-height 1.75. Article prose (`.article p`) opens to 1.9.
- `h1`: serif, weight 400, `clamp(38px, 5vw, 64px)`, letter-spacing -1.6px,
  `text-wrap: balance`, max-width 850px. The home hero `h1` is larger
  (`clamp(46px, 6vw, 76px)`, -2.7px).
- `h2`: serif, 30px, weight 400. `h3`: sans, 19px, weight 550.
- `.eyebrow`: mono, 11px, uppercase, 1.5px tracking, `#526a76`. Every page
  opens with an eyebrow above its `h1`.
- `.lede`: 19px muted intro paragraph, max-width 740px.
- Dates and small labels (timeline, publication year, status chips) are mono.

Exactly one `h1` per page; `check` enforces it. Publication titles are `h2`
inside the list, restyled to 18px sans so they do not read as sections.

## The monogram

The header wordmark is "The researcher's mark": the lowercase text `ms.` set
in Georgia (regular weight, 30px, -2px tracking), ink `#203d54` with the
period in `#397393`. It is real text, not an image, so it needs no asset and
scales with the user's font settings:

```html
<a class="wordmark" href="./index.html" aria-label="Madhu Srinivasan, home"
  >ms<span aria-hidden="true">.</span></a
>
```

The favicon `src/assets/mark.svg` is the same mark on a rounded `#fafbf9`
tile. If the mark ever changes, change both and update the browser tests that
assert the wordmark text, weight, colours and favicon path.

Two handwritten alternatives were drawn from Madhu's actual signature and are
kept for future use in `src/assets/monograms/`: `sm-faithful.svg` (an outline
trace preserving pen-width variation) and `sm-navigation.svg` (an even-stroke
redraw for small sizes). They, every earlier typeface study, and three
self-hosted script fonts are compared on the unlisted `/monograms.html`
gallery (`src/monograms.md`, `src/styles/monograms.css`). Keep the gallery
building; it is the design record. Do not delete the signature SVGs.

## Page templates

Every page is Markdown with HTML where layout needs it, in this order:
front matter `title`, `<p class="eyebrow">`, `# Heading`, `<p class="lede">`,
then content. Links to other pages are relative and end in `.html`
(`preserveExtension: true`): `./about.html` from the root, `../projects.html`
from `src/projects/`.

Home (`index.md`): `.hero` two-column grid (text 1.35fr, figure 1fr) with the
contact links, then `.career-strip`, a `.section-heading` with "All projects",
the `.project-grid`, and a `.research-note` two-column aside.

Project case study (`src/projects/*.md`): eyebrow "Case study · <where>",
`h1`, lede, `.project-meta` (domain, role), one `.article-figure` whose
caption says honestly what the image is, then a `<div class="article">` with
`## The problem`, `## My contribution`, context, `## Related work` with real
links, and a "Back to projects" link.

About: `.article` wrapper, `.timeline` of `.timeline-item`s (mono date column
150px, role on the right), education list, contact links, résumé link.

Unlisted pages set `index: false` in front matter. `layout.mjs` turns that
into `<meta name="robots" content="noindex, nofollow">` and `finalize.mjs`
drops the page from the sitemap. Framework ignores unknown front-matter keys,
so a custom `robots:` key does nothing; use `index: false`.

## Components

| Class                              | Purpose                                                    |
| ---------------------------------- | ---------------------------------------------------------- |
| `.primary-link`                    | outlined accent button; one per page at most               |
| `.contact-links`, `.hero-links`    | wrapped inline link rows, 14px                             |
| `.career-strip`                    | ruled employer/years strip under the hero                  |
| `.project-card` in `.project-grid` | 2-up cards, 190px cover image, serif `h3`, `.topics` chips |
| `.research-note`                   | ruled 1fr/2fr heading + paragraph                          |
| `.article`, `.article-figure`      | 740px prose column, framed figure with grey caption        |
| `.timeline-item`                   | 150px mono date + content                                  |
| `.publication` list                | 68px year column; status chip `.publication-status`        |

Add a new component by extending this list in `site.css`; do not introduce a
CSS framework or utility classes. Page-specific styles (the gallery) go in a
separate stylesheet that `@import`s `./site.css` and is selected per page
with `style:` front matter.

## Imagery

All diagrams are original SVGs made for this site (`field.svg`, `ocean.svg`,
`workflow.svg`): thin blue strokes on a pale grid, illustrative rather than
data. Captions must not imply they are results or screenshots. Do not copy
figures from the private `aboutme` biography; those are unlicensed for the
web. Any new image needs real `alt` text and explicit `width`/`height`.

## Responsive and print

Content column 1056px, nav 1120px, both centred. Breakpoints are `700px`
(everything collapses to one column; nav gaps tighten) and `380px` (nav font
11px, tighter padding, so a 320px viewport has no horizontal scroll; a test
checks this). `prefers-reduced-motion` disables smooth scrolling. Print hides
header, footer and the filter controls and avoids breaking inside a
publication.

## Accessibility rules that tests enforce

- A "Skip to content" link targets `#content`; the publications Markdown
  plugin injects `<span id="content" tabindex="-1">` at the top of every page
  because Framework's `<main>` is not focusable.
- `aria-current="page"` on the active nav link (computed in `layout.mjs`).
- Focus ring: 3px `#245d7c`, 5px offset, on links, buttons, selects.
- Inline links inside prose are underlined. axe flags `link-in-text-block`
  when a link in a paragraph differs from its text only by colour; the
  blue/grey pair here fails the 3:1 contrast test, so the underline is not
  optional.
- Decorative glyph specimens use `role="img"` with an `aria-label`; purely
  decorative images use `alt=""`.
- Live counts use `role="status" aria-live="polite"`.
- Playwright runs axe (`wcag2a`, `wcag2aa`, `wcag21aa`) on every listed page
  in desktop Chromium, mobile Chromium and desktop WebKit. On macOS WebKit,
  Tab skips links; the keyboard test presses `Alt+Tab` there.
- `finalize.mjs` sets `<html lang="en">` and removes Framework's
  `maximum-scale=1` from the viewport meta so users can zoom.

## Things not to do

- No sidebars, pagers, tables of contents or search: the site is a handful
  of pages with a top nav.
- No web-font downloads for the main site. The script fonts belong only to
  the monogram gallery and are self-hosted with their licenses.
- No heavyweight graphics library loaded globally. A future interactive
  project page imports what it needs in its own `js` block.
- No second accent colour, drop shadows, gradients or animation.
